# Remove the 12-model ML ensemble and RL agent; drive the bridge from rule-based momentum with local-backtest self-tuning (v1)

The Python bridge previously decided *timing* with a 12-model neural/tree ensemble and managed exits with an RL agent, while direction was already momentum-based. This change tears out the entire ML/RL layer (models, training/retraining scripts, RL smart-exits, heavy sentiment/alt-data feeds) and replaces the ensemble-derived confidence gate with a rules-derived confidence computed from momentum magnitude — the same `0.2 + 0.7*(1 - exp(-abs_diff/1.5))` curve `backtest.py` already used. Self-tuning now comes from the existing `AutoOptimizer`, which records closed trades from local backtests (and live confirmations) and nudges parameters toward winning values. The CSV signal contract is preserved with `model_name='momentum'` so the unchanged `.mq5` EAs keep working.

Watch for: a momentum-lookback window mismatch between the confidence helper (`data_config.momentum_lookback=8`) and `backtest.py`'s direction/confidence constant (`MOMENTUM_LOOKBACK=6`) — **confirmed**, behavioral but non-breaking; and `AutoOptimizer.get_current_params()` permanently mutating the shared live config each cycle with no reset path — **confirmed**, intended but worth a conscious sign-off. No dangling ML/RL imports, config references, or pruned-dependency imports remain anywhere in the package.

**Verdict**: APPROVED

## High-level view

The removal is complete and internally consistent. Every reference to `models.*`, `EnsembleManager`, `RLAgent`, `PositionState`, `ExitAction`, `SmartExit`, `AutoRetrainer`, and `MODEL_DIR` is gone from retained code and tests, and none of the pruned dependencies (torch, transformers, scikit-learn, hmmlearn, schedule, websocket-client, beautifulsoup4) are imported anywhere. The package AST-parses cleanly across all 29 files.

The confidence-gate replacement is faithful to `backtest.py`'s `compute_momentum_magnitude()` — same formula, same scale, same 0.95 cap — and correctly returns 0.0 when there is insufficient data. The one wrinkle is that the runtime helper's lookback window (8 bars, from `data_config`) differs from the backtest reference (6 bars), so the two paths won't produce identical confidence for the same series. Both are rule-based and sensible; the values just aren't bit-identical.

The self-tuning loop is genuinely wired end to end. `backtest.py` instantiates its own `AutoOptimizer`, records every closed trade, and persists `auto_optimizer_state.json`; `main.py` wires the optimizer into `SignalGenerator` via `set_auto_optimizer` and feeds live confirmations through `record_trade`; and `SignalGenerator` reads `get_current_params()` at signal time to override `min_confidence`, `momentum_lookback`, session multipliers, and RSI levels. This closes the "backtest locally so it can tweak itself" loop the user asked for. Note that the override mutates the generator's shared config objects in place and never restores them — fine because the optimizer converges, but it means config drifts monotonically with the tuner.

The new and rewritten tests exercise real logic rather than asserting static values. The AutoOptimizer self-tuning tests drive `record_trade` until a cycle fires and assert the parameter actually shifts toward the winner (8→9), persists to the named JSON, reloads across a fresh instance, and rolls back on a simulated regression. The backtester tests build an analytically-tuned zigzag series that provably clears every entry gate, then assert closed trades carry a rule-derived (non-0.5) confidence and a valid trailing tier. These would fail if the rule-based path regressed. The DataFrame-dependent suites cannot execute in this offline sandbox (no pandas/numpy/ta), so their quality is verified at source level only.

### Rules-derived confidence replacing the ensemble gate

The behavioral seam worth flagging: `_compute_momentum_magnitude` reads its lookback from `data_config.momentum_lookback` (8), while the backtest reference constant `MOMENTUM_LOOKBACK` is 6. Same curve, different window. A `$2.40` move over 6 bars and over 8 bars generally won't be equal, so a parameter set that looks good in the local backtest will map to a slightly different live confidence. This is not a correctness bug — both are rule-based — but it undercuts the "backtest locally so it can tweak itself" premise slightly, since the tuner optimizes against a 6-bar world and the live generator lives in an 8-bar one.

The old `models_loaded` HOLD gate and the checkpoint-directory fallback are gone, so the generator never refuses to trade for lack of a model — it proceeds on momentum/RSI as the backtest engine does. `update_from_execution` and `register_open_position` were stripped of all RL state (`PositionState`, reward/transition/train_step, the excursion-tracking dict fields) down to risk-manager close plus lightweight bookkeeping, with the now-unused `predicted_action`/`actual_outcome` args retained only for interface compatibility.

### Local-backtest self-tuning loop

```
backtest.py                              main.py (live)
  AutoOptimizer(state_dir)                 AutoOptimizer(AutoOptimizerConfig)
  run(df):                                 __init__: signal_generator.set_auto_optimizer(...)
    close trade -> record_trade(ctx)       confirmation FILLED/CLOSED:
    every N -> _run_optimization             pnl -> record_trade(trade_context)
    save_state() -> auto_optimizer_state.json
        │                                        │
        └──────────────► SignalGenerator.generate_signal:
                           opt = get_current_params()
                           signal_config.min_confidence   = opt[...]
                           data_config.momentum_lookback   = opt[...]
                           session_config.*_multiplier     = opt[...]
                           data_config.rsi_*               = opt[...]
```

`_check_rollback()` is invoked from inside `record_trade` in production (not only from tests), so the regression-rollback path is genuinely reachable.

The override at `get_current_params()` mutates the generator's shared config instances in place and never restores them. Because the optimizer shifts one clamped step per cycle and converges, this is the intended "tunes itself and stays tuned" behavior — but there is no snapshot/restore, so the live config drifts monotonically for the life of the process and the only way back to defaults is a restart. Worth a conscious sign-off rather than a fix.

### Test coverage

The AutoOptimizer self-tuning tests are the strongest addition: `test_param_shifts_toward_winner_over_a_cycle` feeds a winning lookback (10, all profitable) against a losing one (5), drives them through `record_trade` past `optimize_frequency`, and asserts `momentum_lookback` moved 8→9 (one clamped step) within its configured range. `test_tuned_state_persists_to_named_json` asserts the state file is written with the documented name and that a fresh optimizer reloads the tuned value. `test_regression_triggers_rollback_end_to_end` arms a rollback with an 80% pre-optimize window, fills a 0% post window through `record_trade`, then asserts params restore to pre-tuning. These exercise the real code path and would fail on a logic regression.

The backtester integration tests build a net-up zigzag (`+$2.00`/`-$1.20` alternating) that is analytically tuned to clear every gate — 6-bar momentum `+$2.40 > $1.50`, Wilder RSI converging to 62.5 inside the BUY zone, TR inside the ATR band — then assert `>=1` closed trade with a rule-derived confidence in `(0, 0.95]`, a valid `trail_tier`, and `any(c != 0.5)` to prove confidence isn't a hardcoded constant. `test_backtester_and_optimizer_wired_end_to_end` runs a 600-bar backtest and asserts `trade_count == total_trades`, `cycle_count >= 1`, params changed from defaults, and state persisted.

Not executed: `test_backtester`, `test_signal_generator`, `test_bridge`, `test_multi_timeframe`, `test_news_calendar`, `test_smart_upgrades` all import pandas/numpy/ta, which are absent and uninstallable in this offline sandbox. Their correctness is verified only by AST parse and source review; a real pandas/numpy environment is needed to confirm the DataFrame paths actually run green. The pure-Python suites (`test_auto_optimizer`, `test_dashboard`) pass 118/118 here.
